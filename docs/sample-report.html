#2 Cross Site Scripting (Reflected)

Высокая CVSS не оценён · Открыта · demo-shop

Где
https://shop.example.test/search
Параметры
q

CWE-79

Ответственный
team-search
Срок по SLA
2026-10-31 (просрочено на 4 дн.)
Впервые / последний раз
2026-10-01 / 2026-10-12

Описание

The search term is reflected into the HTML response without encoding, so a crafted link runs attacker JavaScript in the victim's browser.

Как воспроизвести

GET https://shop.example.test/search?q=test
Параметр: q
Атака: <script>alert(1);</script>
Признак в ответе: <script>alert(1);</script>

Как исправить

Encode output for the HTML context (use the template engine's auto-escaping), validate input, and add a Content-Security-Policy that forbids inline scripts.

Ссылки

  • https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html
  • https://cwe.mitre.org/data/definitions/79.html

Впервые / последний раз

Описание

A path normalization flaw in Apache HTTP Server 2.4.49 lets an attacker read files outside the document root.

Как воспроизвести

Шаблон CVE-2021-41773 сработал на https://shop.example.test/cgi-bin/.%2e/.%2e/.%2e/.%2e/etc/passwd
Извлечено: root:x:0:0:root:/root:/bin/bash
Воспроизведение: curl -X 'GET' --path-as-is 'https://shop.example.test/cgi-bin/.%2e/.%2e/.%2e/.%2e/etc/passwd'

Как исправить

Upgrade Apache HTTP Server to 2.4.51 or later.

Ссылки

  • https://nvd.nist.gov/vuln/detail/CVE-2021-41773
  • https://httpd.apache.org/security/vulnerabilities_24.html

Впервые / последний раз

Описание

The profile edit form has no anti-CSRF token, so another site can submit it on behalf of a logged-in user.

Как воспроизвести

GET https://shop.example.test/profile/1024/edit
Признак в ответе: <form action="/profile/1024/edit" method="post">

Add a per-session anti-CSRF token to state-changing forms and set SameSite on the session cookie.
